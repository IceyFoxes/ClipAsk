# ClipAsk

Build from the repository root with `.devin/tools/dotnet-win/dotnet.exe build ClipAsk.slnx -c Release --nologo`.

Run tests with `.devin/tools/dotnet-win/dotnet.exe test tests/ClipAsk.Core.Tests/ClipAsk.Core.Tests.csproj -c Release --no-build`.

Run the desktop prototype with `bash scripts/dev.sh run` or the Release `ClipAsk.dll` using the project-local native SDK and Codex executable. `bash scripts/dev.sh verify` runs the Release build, focused tests, synthetic UI smoke mode, and isolated provider probe. The PowerShell scripts remain available when the existing execution policy allows `-File`; the WSL launcher uses WSLENV path translation and does not bypass policy. Native Codex runtime state intentionally defaults to `%LOCALAPPDATA%\\ClipAsk`; source, SDK, Codex binaries, and NuGet caches remain project-local.

The app is a native WPF screenshot-to-answer utility. Keep ChatGPT account authentication in the official managed browser flow, never use API keys or credential migration, and never auto-upload screenshots before explicit capture and answer actions. Keep captures local until the user releases a valid selection. Do not add chat, OCR, history, speculative uploads, or full editing in the prototype. A scoped optional instruction and an eligible account-advertised model choice may live in Answer options; do not turn either into a follow-up chat flow. Do not change ordinary PrtSc behavior or Windows settings. Keep all model prompts, policy settings, and capture timing semantics centralized in the authored files under `src/ClipAsk.Core/Providers` and `src/ClipAsk.Core/Diagnostics`. Native Codex stdin/stdout/stderr use no-BOM UTF-8; never depend on the GUI default code page.
The current measured preference is GPT-5.6-Terra with low reasoning when the account advertises that configuration for images; otherwise retain the supported catalog default. This was selected from a small account-specific synthetic comparison, not a universal speed guarantee. Keep the standard service tier and do not rerun live benchmarks without an explicit user-approved test budget. A user-approved six-turn comparison found priority about 0.60 seconds faster at median on three synthetic inputs, but the user chose standard as the default to preserve subscription allowance.
